# 网易云桌面歌词

自己做的网易云音乐（PC 3.x）桌面歌词：透明、置顶、可鼠标穿透，偏移能按 0.01 秒微调。

## 用法

- 双击桌面「网易云桌面歌词」。右下角托盘出现红色「词」图标就是开着了。
- 在网易云里放歌，歌词自动出现在屏幕下方。
- 鼠标移到歌词上会出现工具条。**左边是字幕样式，右边是功能**：
  - 左边（样式）
    - 译 / 下句：可以同时开。从上到下是「当前这句（大）→ 翻译（中）→ 下一句（小、淡）」。
      有翻译的歌，某句没翻译时翻译那行空着，下一句不会跳来跳去；整首都没翻译的歌，下一句直接贴在当前句下面。
    - 逐词：一句歌词不一下子全出来，而是唱到哪个词出哪个词（中文按字，英文按单词），每个词淡入一下。
    - 渐变：唱到哪里，白字就从左到右变成主题色（网易红、暖金……）。关掉就没有这个动画，整句直接是主题色；
      两种状态的描边完全一样。
    - 间奏：没人唱的时候标出「（前奏）（间奏）（尾奏）」。
    - A− A+：字号。
    - 配色 ▾：下拉选颜色，每个选项前面有色块预览，当前用的打 ✓。预设有网易红、清新蓝、暖金、薄荷绿、纯白、樱花粉、星空紫；
      最下面「挑一个颜色…」可以自己调，拖的时候歌词实时变色，按取消就还原。托盘菜单的「配色」里也是同一套。
  - 右边（功能）
    - `−0.1 / −0.01 / +0.01 / +0.1`：调偏移。**+ 是歌词提前，− 是歌词推迟**。
    - 中间那个显示偏移的按钮：滚轮 ±0.01 秒，按住 Shift 滚 ±0.1 秒，右键归零。
    - 「全部歌曲 / 只调这首」：点一下切换。平时调「全部歌曲」（耳机、音箱的固有延迟），某首歌词本身对不齐再切到「只调这首」，那首歌会单独记住。
    - 找词：这首没歌词（或者网易云说是纯音乐）时点一下，重新去别的歌词库找，找不到就用 AI 听写。
    - 校准：觉得这首的逐字对不上就点一下，按这首歌的声音重新对齐每个字。模型已经加载时，你正在听的那几句 1～2 秒就对好，
      整首十来秒；进度只在歌词上方的小条里提示，不占翻译的位置。
    - 锁定 / ✕（隐藏）。
- 提示消息（偏移改了多少、从哪补的歌词、校准进度）都显示在歌词上方的一个小条里，不会盖住歌词和翻译。
- 拖动歌词条移动位置，拖左右边缘改宽度。
- 锁定后鼠标能穿透歌词，鼠标移上去会在原来「锁定」的位置出现「解锁」，同一个地方点就能来回切。点托盘图标也能解锁。

## 拖进度条之后歌词不准？已经自动处理

- 查出来的原因：**网易云自己的播放进度在拖进度条之后会和真正放出来的声音错开**，而且一直错到下一次拖动或换歌。
  在这台电脑上实测（录下扬声器的声音和歌曲文件比对）：从头正常播放时误差只有几十毫秒；拖过一次后进度比声音快了 1.0 秒，
  另一次快 0.6 秒，每次不一样。歌词钟跟着网易云的进度走，所以歌词跟着提前了。按「校准」改的是每个字的时间，管不了这个。
- 现在的做法：每次拖进度条（或暂停后继续）约 1 秒后，程序听 1.6 秒扬声器正在放的声音，在这首歌的缓存音频里找到这段，
  算出网易云进度差了多少，直接把歌词钟拨正；平时每 30 秒再核对一次。录到的声音只在内存里比对，不保存、不上传。
  还没核对完的那一两秒，先按以往拖动后的平均偏差先挪着。
- 托盘「拖进度条后听声音自动对时」可以关掉。核对记录在 `data/sync.log`。
- 这里对的是「发给扬声器的声音」，蓝牙耳机自己的延迟还是用「全部歌曲」的偏移调一次。

## 流畅度

- 逐字变色、逐词出现这些动画，按显示器的刷新来出帧（等系统合成器的每一次刷新再画），不再用固定 8 毫秒的计时器。
  在这台 180Hz 的显示器上每 2 次刷新出一帧（90 帧/秒），实测 99% 的帧间隔正好 2 次刷新；
  以前固定计时器下是一半隔 1 次、一半隔 2 次，所以扫过去会一顿一顿的。144Hz、120Hz、60Hz 的屏每次刷新都出一帧。
- 没有动画的时候不出帧，只在下一句该出来时醒一下。
- 动画时一个 CPU 核心的占用从 5.7% 降到 3.5%：只重画变化的那一行、截断文字和字距的计算结果缓存起来、
  计时器不再每帧重启、后台线程更快把界面线程的时间还回来（换歌时解码音频不会让歌词卡一下）。

## 快捷键（任何时候都能用）

| Ctrl+Alt+= / Ctrl+Alt+− | 歌词提前 / 推迟 0.01 秒 |
| Ctrl+Alt+Shift+= / − | 提前 / 推迟 0.1 秒 |

| Ctrl+Alt+L | 锁定 / 解锁 |
| Ctrl+Alt+H | 显示 / 隐藏 |

（小键盘的 + − 也行）

## 歌词从哪来

1. 网易云自己的歌词（有逐字时间轴的歌会逐字变色）。
2. 网易云没有、**或者网易云标了「纯音乐」**（冷门歌常常只是没人上传歌词就被标成纯音乐）时，依次去网易云的其他版本、
   LRCLIB、QQ音乐找同名同歌手、时长差不到 3 秒的版本。只有一两行、写着「纯音乐，请欣赏」之类的占位不算歌词。
3. 还是没有，就用 AI 听写（下面）。网易云标了纯音乐的歌先听有没有人唱：几乎没人声就直接显示「纯音乐」；有人声就听写，
   听出来不到 3 句 / 8 个词（多半是人声采样）也算纯音乐。判断结果会记住，不会每次放都重算；想重来就点「找词」。

找的过程会显示在歌名下面（「正在别的歌词库找…」「纯音乐？正在听有没有人唱…」「AI 听写：识别歌词…」）。

## 原理

- 网易云 3.x 的系统媒体接口（SMTC）只给歌名、不给进度，所以普通歌词软件只能靠猜。
  这里直接读网易云自己内存里的播放进度、歌曲 ID 和播放/暂停状态，跟网易云自己的进度条同一个来源。
- 网易云大约每 30 毫秒写一次进度；程序在两次之间用本机高精度时钟补齐，误差在几毫秒内。拖进度条后的偏差见上面。
- 下载过的歌词存在 `data/cache/`（别处补来的存为 `<歌曲ID>.alt.json`，没找到的 3 天后再找一次）。
- 只有整句时间的歌，逐词出现用的是估算时间：按音节数（中文一字一个、英文数元音组、日语按假名拍子）把这句的时长分给每个词，
  并且一句最多按每音节 0.42 秒唱，不会把一句短词拉长到整段间奏。之后自动校准会换成按声音对齐的时间。
- 定位进度用的特征码来自 [Kxnrl/NetEase-Cloud-Music-DiscordRPC](https://github.com/Kxnrl/NetEase-Cloud-Music-DiscordRPC)。
  网易云大版本更新后如果特征码失效，歌词条会提示「读不到网易云的播放进度」，需要更新特征码。

## 后台的显卡助手（`worker.py`）

- 校准和 AI 听写都交给一个常驻的后台进程，Demucs 和 Whisper 加载一次就一直留在显卡上，不用每首歌重新加载约 4GB 模型。
- 一开始放歌就让它先把模型加载好；5 分钟没活干就自己退出，把显存还给游戏。
- 第一次启动（要加载模型）大约 19 秒出第一批校准结果，之后每首歌约 2 秒。歌词窗口本身不加载 PyTorch。

## 自动校准怎么做的

- 每首歌第一次放时，歌词先照常显示，同时后台从**你正在听的位置**开始，每次分离 30 秒人声、把这段里的句子对齐，
  对好一段就换上一段；整首做完存成 `data/cache/<歌曲ID>.align.json`，以后再放直接用；网易云的歌词改了会自动重新校准。
  自动校准不出提示，托盘「按音频自动校准逐字时间」可以关掉。
- 做法：每一句单独切一个小窗（从这句附近人声真正响起的地方开始，到下一句开始），用 Whisper 把已知的歌词文字对到声音上，
  每个字的起止再贴到人声真正有声音的地方。（试过几句一起对：Whisper 会把句子之间的停顿算给下一句第一个字，句首早好几秒。）
- 只有整句时间的歌：每个字换成对齐出来的时间（变成真正的逐字）；如果整句时间偏晚，句首也提前到人声开始处。
- 网易云本来就有逐字时间的歌：不改它字和字之间的间隔，只在「网易云说这句开始的地方人声是静的、而附近有明确的人声起点」时整句挪过去。
- 在缓存里有网易云逐字歌词的歌上打分（给句首加了 ±0.3 秒随机误差模拟不准的整句时间）：
  - 句首：误差中位数 0.03～0.10 秒，88～96% 在 0.25 秒内。
  - 句内每个字：日语从原来估算的 0.8 秒左右降到 0.24～0.35 秒；英语和原来估算差不多（0.2～0.35 秒）。

## AI 听写怎么做的

- 音频来自网易云自己的缓存（`Cache\Cache\<歌曲ID>-<码率>-*.uc`，就是原始音频每个字节异或 0xA3），
  所以第一次放就能听写，不用录音。缓存没下完会等它（最多 90 秒）。
- 先用 Demucs（htdemucs）把人声从伴奏里分出来，再用 Whisper large-v3（faster-whisper，显卡 float16）带逐字时间听写。
- 语言：从歌曲几个地方抽样判断，再参考歌名的文字（有假名→日语、有韩文→韩语、只有汉字→中文，除非声音明显不是）。
  中文会提示用简体。
- 人声检测阈值调松了（默认值是给说话用的，会把唱的句子当静音丢掉）：在几首缓存歌上对比，
  文字吻合 38～79%，句子开头时间误差中位数 0.36～0.53 秒。伴奏很重、人声很少或做了特殊处理的歌会听得很差。
- 过滤：Whisper 在静音处常编的「字幕 / 谢谢观看 / 订阅」之类整句丢掉；把握太低的句子丢掉；同一句连续重复太多次截掉。
- 切歌会立刻取消上一首的活。失败原因记在 `data/ai_errors.log`，后台进程的输出在 `data/worker.log`。
- 模型在 `data/models/`（Whisper 约 3.1GB，Demucs 约 80MB），PyTorch 装在 Python 里（CUDA 12.8 版，50 系显卡要这个版本）。

（之前试过在间奏里标出在响什么乐器，准确度不够，已经拿掉；当时下载的 CLAP 模型还留在 `data/models/clap`，约 600MB，可以删。）

## 文件

- `main.pyw` 入口：托盘、全局快捷键、只允许开一个
- `ncm_reader.py` 读网易云播放进度 + 平滑时钟（也报告拖动 / 继续播放）
- `audiosync.py` 拖进度条后听扬声器的声音把歌词钟拨正
- `lyrics.py` 取歌词、解析 LRC / 逐字 YRC、缓存、别处补歌词、逐词时间估算
- `overlay.py` 歌词窗口
- `worker.py` 常驻显卡助手（校准、AI 听写）；`worker_client.py` 歌词窗口这边和它说话
- `align.py` 按声音对齐每个字；`transcribe.py` 解码缓存音频、分离人声、听写
- `config.py` 设置（存在 `data/config.json`）

依赖：Python 3.12、PySide6-Essentials、requests、pywin32、soundcard；AI 听写 / 校准另需 torch（cu128）、demucs、faster-whisper。
